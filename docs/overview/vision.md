# roshanavi — ビジョン

ROS 2 システムの「通信の可視化」「ダミー入力の注入」「入出力シナリオの自動判定」を 1 つの Web UI / CLI にまとめるツール。

## 出発点と対象ユーザー

- **課題**: ROS 2 のテスト・確認手段 (`ros2 topic hz/echo/pub`, rqt_graph, rqt_publisher, launch_testing, bag ...) が分散しており、一つの UI になっていない。それぞれの使い方と組み合わせ方を知っていることが前提になっている。
- **対象**: ROS を深く理解していない開発者が、ROS のノードを開発・確認できること。ROS 熟練者が CI で使えることは副次的なゴール。
- **設計への含意**: CLI の知識や YAML 手書きを前提にしない (UI で完結し、YAML は保存・CI 用の形式)。用語 (QoS 等) は UI 上で平易に補足し、つまずきやすい点 (QoS 不一致、subscriber 不在 など) はツール側から指摘する。

## 主要ユーザー体験: ノード単体開発者の 1 日

「自分のノードを作っている人」が、ROS のコマンドを覚えずに **起動 → 入力 → 観察 → テスト化 → 修正 → 再確認** を GUI で回せること。

1. **ツールを起動**: ワークスペースで 1 コマンド (`ros2 run roshanavi app`)。ブラウザが開く。
2. **プロジェクトを開く**: プロジェクトファイル (`roshanavi.yaml`) に、起動対象・ダミー入力・監視トピック・シナリオを保存する。初回はワークスペースを走査して作る。
3. **ノードを起動 (Launcher)**: 自分のノードと依存ノードを GUI で選んで起動・停止・再起動する。
   - 候補はワークスペースから自動で列挙する (パッケージの実行ファイル、launch ファイル)。
   - パラメータとリマップを GUI で設定できる。プロセスごとにログ (stdout/stderr) を表示する。
   - **ビルドボタン**: `colcon build --packages-select <pkg>` を実行し、成功したら対象ノードを自動で再起動する。
4. **ダミー入力**: 入力トピックを選び、手入力・式・ファイル (画像/動画/音声/JSONL/CSV)・bag から送る。
   - **恒久ノード化**: ダミー入力を、GUI のジョブではなく独立した ROS ノード (例: `/dummy_camera`) として常駐させる。
     - 名前付きでグラフに現れ、ツールの起動時に自動で起動できる (プロジェクトに保存)。
     - launch ファイル + 設定 YAML に書き出し、ツールなしでも `ros2 launch` で動かせる。
5. **観察**: 出力トピックをエコー、グラフ、プロット、**画像ビューア**、**音声の波形・再生**で確認する。
6. **テスト化**: 記録モードで、いまの操作と出力をシナリオに保存する ([scenarios.md#UI での作り方](../design/scenarios.md#ui-での作り方-記録モード-主軸))。
7. **修正ループ**: コードを直す → ビルドボタン → ノードが自動で再起動 → 保存済みシナリオを一括再実行し、回帰を確認する。

### 実行形態
- 利用者のノードと同じ ROS 環境で動く必要があるため、**本番の形はネイティブ実行** (利用者のワークスペースに入れて colcon build、将来は apt)。
- Docker は開発・CI・デモ用に位置づける。Docker で使う場合は、利用者のワークスペースをマウントする。

### 同梱サンプルノード (`roshanavi_examples`, P5)
チュートリアル、デモ、自動テストの対象を兼ねる。教材なので、各ファイルの先頭に「何を受けて何を出すか・パラメータ・実行例」を書き、本文もコメントを多めにする。詳細は [nodes.md#同梱サンプルノード](../design/nodes.md#同梱サンプルノード-roshanavi_examples-p5)。
- `image_filter` (C++): Image → グレースケール + エッジの Image (stamp 引き継ぎあり/なしをパラメータ `keep_stamp` で切替 → latency の両モード検証用。`process_delay_ms` で遅い処理を再現)
- `blob_detector` (C++): Image → `vision_msgs/Detection2DArray` (明るい塊の bbox とスコア。配列長・座標の判定用)
- `audio_level` (Python): 音声 (AudioDataStamped / Int16MultiArray) → 音量 (dB) と無音フラグ (ヒステリシス付き)
- `state_machine` (Python): `/cmd` (start/stop/fault/reset) → `/state` (IDLE/RUNNING/ERROR) (guards・状態遷移の判定用)

### 変換ノード (コードを書かずに作る、P5)
トピックを受けて、式で変換して別のトピックに送るノードを GUI で作る (未実装ノードの代役・型や名前の違うトピックのつなぎ・遅延や間引きを入れた意地悪テスト)。詳細は [nodes.md#変換ノード](../design/nodes.md#変換ノード-p5)。

### 関数ノードと「データの種類」(初心者向け、P5.5)
- **関数ノード**: ROS を知らない人でも、普通の Python 関数を書くだけで自分のロジックをノードとして動かす。受信・呼び出し・送信・型の変換は roshanavi が受け持ち、ファイルを保存すると自動で読み直す。卒業用に、同じ動きの rclpy ノードのコードを書き出せる。詳細は [nodes.md#関数ノード](../design/nodes.md#関数ノード-ふつうの関数をそのままノードにするp55)。
- **クラスノード**: 状態を持つ処理 (移動平均・カウンターなど) は、普通の Python クラスのまま動かせる。`__init__` の引数は ROS パラメータ、メソッドはトピックや「リセット」のような操作ボタンに結びつき、`lifecycle` ノードとしてコードを書き出して ROS の流儀を学ぶこともできる。詳細は [nodes.md#クラスノード](../design/nodes.md#クラスノード-状態を持つ処理をそのままノードにする)。
- **データの種類**: 入力ノード・変換ノード・関数ノード・お試し送信で、ROS のメッセージ型ではなく「文字列・数値・画像…」を選ぶ。ROS の型は詳細設定モードでだけ直接選ぶ。詳細は [nodes.md#データの種類](../design/nodes.md#データの種類-ros-のメッセージ型を意識させないp55)。

## ゴールと非ゴール

**ゴール**
- G1 グラフ: ノード ⇄ トピックの接続図を QoS 付きでリアルタイム表示。エッジを Hz / 帯域で強調。
- G2 トラフィック: 全トピックの Hz・帯域・平均サイズ・ジッタ・最終受信時刻を一覧 + スパークライン。
- G3 注入: 任意型のトピックへ 単発 / 周期 / 式 / ファイルストリーム (JSONL・CSV) / bag 再生 で入力。
- G4 シナリオ: YAML で「注入 → 期待出力」を記述し、UI と CLI (JUnit XML, exit code) で判定。CI 可。
- G5 エコー: 選択トピックの最新メッセージを UI で確認。画像は表示、音声は波形と再生。
- G6 Launcher: 自分のノード・依存ノードの起動・停止・再起動・ログ表示・ビルド ([vision.md#主要ユーザー体験](vision.md#主要ユーザー体験-ノード単体開発者の-1-日))。
- G7 恒久ダミーノード: ダミー入力を名前付きの常駐ノードにし、launch ファイルとして書き出せる ([vision.md#主要ユーザー体験](vision.md#主要ユーザー体験-ノード単体開発者の-1-日))。
- G8 メディア注入: 画像・動画 (フレーム分解)・音声ファイルを適切な msg に変換して送る ([input-and-media.md#メディアファイル注入](../design/input-and-media.md#メディアファイル注入))。

**非ゴール (MVP)**: サービス・アクション (今後対応予定。README に明記する)、CARET 級のコールバック単位レイテンシ解析、複数ドメイン同時監視、認証付きリモート公開。
