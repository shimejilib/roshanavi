# roshanavi — P4.5 デモ体験とランチャーの改善

P4 完了後に実装し、DESIGN.md へ統合する。

## 1. デモの基本の流れ
1. **入力ノード (= 新しいトピック) を作る**: 「＋ 入力ノードを作る」から、トピック名・型・中身 (文字列・式・画像・音声など) を選ぶと、名前付きの常駐ダミーノードとして地図に現れる。
   - 「注入してから常駐化」の 2 段階をやめ、1 ステップで作る (既存の注入ジョブは「お試し送信」として残す)。
   - 新しいトピック名を入れれば、そのトピックも同時に現れる (ROS 2 のトピックは publish / subscribe された時点で存在するため、「トピックを増やす」=「新しい名前に送るノードを作る」)。
   - 地図の空白を右クリック →「ここにトピックを追加」からも同じダイアログを開ける。
2. **サンプルノードを起動する**: デモではランチャーの一覧に同梱サンプル (P5) とデモ用パッケージだけを出す。
3. **地図で流れを見る**: ダミー → ノード → 出力の流れと、出力の中身を確認する。
4. (P6) 操作を記録してシナリオにする。

## 2. デフォルトのサンプルプロジェクト
- `examples/demo_project/roshanavi.yaml` を用意する。中身は以下のとおり。
  - `talker` (demo_nodes_cpp, role: mine, autostart)
  - `listener` (demo_nodes_cpp, role: dependency, autostart)
  - (P5 以降) サンプルノードの起動設定 (autostart は off)
- compose の `lab` は、`/data/roshanavi.yaml` が無ければこのサンプルをコピーして使う (既存のプロジェクトは上書きしない)。
- これにより、デモ開始時点で talker / listener がグラフから停止・再起動でき、ログも見られる。

## 3. 外部ノードの例 (`demo` コンテナ)
- `demo` コンテナの役割を「roshanavi が起動していないノード」の例に変える。
  - `ros2 run demo_nodes_cpp talker --ros-args -r __node:=external_talker -r chatter:=/external/chatter`
  - (任意) `/external/chatter` を受ける外部 listener
- `/chatter` とは混ざらず、地図上で「操作できるノード」と「見るだけのノード (停止ボタン無効)」が並ぶ。

## 4. ランチャーの改善
- **初回の案内**: 起動リストが空なら、3 ステップの説明と「試しに talker を起動してみる」ボタンを出す。
- **操作の単純化**: 「＋ ノードを起動」→ 選ぶ →「起動」だけにする。詳細設定 (パラメータ・リマップ・名前空間など) は「詳細設定」に畳む。
- **登録と保存は自動**: 起動したものは自動で起動リストに残り、プロジェクトファイルにも自動で保存する (明示的な保存ボタンと「未保存」表示をなくす。読み直しは設定メニューへ)。
- **一覧の絞り込み**: 既定はワークスペースのパッケージ (デモではサンプル + デモ用) のみ。「ROS 標準パッケージも表示」で全件を出す。ワークスペースが未設定なら、マウント・設定方法を案内する。
- **用語の補足**: launch ファイル、リマップ、名前空間、パラメータなどにツールチップで平易な説明を付ける (例: 「launch ファイル = 複数のノードをまとめて起動する設定ファイル」)。
- 「起動対象」という表記は「起動リスト」に変える。

## 5. 地図の右クリックメニュー
| 対象 | メニュー |
|---|---|
| 自分 / 依存ノード | 停止・再起動・起動、ログ、起動設定を編集、ビルドして再起動、パラメータを見る・変更する、入出力だけ表示 |
| ダミーノード | 停止、一時停止・再開、内容・レートの変更、launch に書き出し |
| 外部ノード | パラメータを見る、入出力だけ表示、詳細 (送受信トピックと QoS) |
| トピック | 中身を見る (エコー / 画像 / 音声)、お試し送信、入力ノードを作る、録画、監視 ON/OFF、型の定義を見る、上流・下流だけ表示 |
| エッジ | QoS の詳細、届かない理由 |
| 空白 | トピックを追加、ノードを起動、整列し直す、全体を表示 |

- パラメータの取得・変更は、rclpy のパラメータサービス (list/get/set) で行う。外部ノードは閲覧のみを既定とし、変更は確認ダイアログ付きにする。
- 型の定義は `rosidl` のインタフェース定義 (`ros2 interface show` 相当) を表示する。

## 6. ノードをクリックしたときの入出力データ表示
- 右ペインに「受信しているデータ」と「送信しているデータ」の 2 セクションを出し、トピックごとに最新メッセージ・Hz・型を表示する (画像・音声トピックはサムネイル / 波形)。
- 表示しているのは **トピックに流れているデータ** であり、そのノードが実際に受け取ったものとは限らない。QoS 不一致の場合は「このノードには届いていません」と明示する。
- 負荷対策: 各トピックは折りたたみで、開いている間だけ購読する (既定では最初の 3 つまで自動で開く)。heavy 型は開いたときだけ表示する。

## 7. トラフィックの更新タイミングの改善
- 一定時間 (期待周期の 3 倍、最低 1 秒) 届かなければ、Hz を即座に 0 (停止) と表示する (5 秒平均の残留をなくす)。
- 計算期間 (1 / 5 / 10 秒) を UI で切り替え可能にし、「直近 5 秒の平均」のように画面に明記する。

## 8. ノード一覧画面 (新タブ)
リストとチェックボックスで、ノードを一括で ON/OFF する。

- **一覧の中身**: 実行中のノード (グラフ) と、登録済みだが停止中のノード (起動リスト・常駐ダミー) の和集合。
- **列**: チェックボックス、ノード名、役割 (自分 / 依存 / ダミー / 外部)、状態、起動元 (パッケージ・実行ファイル・launch ファイル)、PID、(P8 以降) CPU・メモリ。
- **一括操作**: 選択したノードの起動・停止・再起動、全選択、役割と状態での絞り込み、検索。
- 1 つの launch や composable container に属するノードは、まとめて止まることを行のグループ表示と確認ダイアログで示す。
- **外部ノード**: チェックボックスを無効にし、理由をツールチップで示す。ただし **lifecycle ノード** は、ROS の正規の仕組み (lifecycle サービスでの activate / deactivate) で ON/OFF できるようにする (プロセスにシグナルは送らない。確認ダイアログ付き)。
- **既存環境の取り込み (launch の分解)**: 利用者の既存の launch ファイルを解析し、中の Node アクションをノードごとの起動設定 (パラメータ・リマップ・名前空間込み) として起動リストに取り込む。これにより、既存システムのノードを 1 つずつ ON/OFF できる。
  - 解析には launch の LaunchDescription を評価し、Node アクションを抽出する方式をとる。
  - 条件分岐・include・composable node など、分解できない要素は「分解できない部分」として launch 全体のまま取り込み、理由を表示する。
- **最終更新の表示**: トラフィック表と地図に「最終更新 12:34:56 (2 秒前)」を常に表示する。WebSocket の切断や更新の遅れが分かるように、5 秒以上更新がなければ警告色にする。各行の「最終受信」(last_seen) とは別物であることを、ラベルで区別する。
- **Hz の計測方法ラベルの見直し**: 現在の「(送信側)」表示は、送信時刻ベースで計算したこと (`hz_basis: source`) を意味するが、初心者には「送信側の Hz」と誤読される。既定では表示せず、受信時刻ベースに切り替わったとき (精度が落ちたとき) だけ「(受信時刻で概算)」と出す。詳細はツールチップ (ⓘ) に回す。
