# 地図の上での配線 (設計・未実装)

目標: **pub/sub だけ知っていれば、地図の上で線をつないでロジックを書くだけ**でノードを作れるようにする。トピック名を文字で打たない、型を意識しない。

## 1. 体験
1. 地図の上で「＋ 関数・クラスノードを作る」(または、ひな形・既存のモジュールから関数・クラスを選ぶ)。
2. 関数・クラスのノードが地図に置かれる。入力 (引数・処理メソッド) と出力 (戻り値) が「つなぎ口」として表示される。
   - 例: `def shout(text: str) -> str` → 左に入力口 `text (文字列)`、右に出力口 `戻り値 (文字列)`。
   - クラスなら、処理メソッドごとに入力口・出力口、操作メソッド (reset など) はボタン。
3. **既存のトピックから入力口へドラッグ**すると、そのトピックを購読する。
   - データの種類が合わない組み合わせは、つなぐ前に「文字列の入力口に、画像のトピックはつなげません」と表示し、線を引かせない。変換できる組み合わせ (整数 → 小数など) は許可して、その旨を表示する。
4. **出力口から空白へドラッグ**すると、新しいトピックが作られる。名前は自動で提案する (`/<ノード名>/<戻り値の名前>`、編集可)。既存のトピックへドラッグすると、そこへ送る (型が合う場合のみ)。
5. 線をつないだ瞬間に動き出し、線の上をデータが流れる (既存の流れのアニメーション)。出力口の上にマウスを置くと、最新の値が見える。
6. 線を選んで削除、つなぎ替えもドラッグで行う。

## 2. 呼ばれ方の表示 (案 D の一部)
- 入力口が 1 つ: 「この入力が届くたびに呼ばれます」
- 入力口が 2 つ以上: 結合ルールを図で示す (「どれかが届くたびに、全部の最新の値で呼ばれます」/「A が届いたときだけ、B の最新の値と一緒に呼ばれます」) を切り替えられる
- 入力口なし: 「10 Hz で呼ばれます」(周期を編集可)

## 3. 実装の方針
- 地図 (cytoscape) にノードの「ポート」を描く。既存のノード要素の左右に小さな要素を付け、ドラッグで線を作る (cytoscape の拡張 edgehandles 相当。ライセンスを確認してから採用、無ければ自前で実装)。
- 配線の結果は、既存の関数・クラスノードの設定 (入力トピック・出力トピック・データの種類) に書き込むだけにする。新しい保存形式は作らない (プロジェクトファイルの `functions:` / `classes:` と同じもの)。
- 配線できるのは roshanavi が動かす関数・クラス・変換・入力ノードのみ。利用者が書いた ROS ノード (外部・ランチャー起動) のトピックは、線の始点・終点として使えるが、そのノード自体の配線は変えられない (コードの中で決まっているため) と表示する。
- 操作はすべてキーボードでも行えるようにする (ポートを選ぶ → つなぐ先を選ぶ)。

## 4. 言葉の総点検 (案 A)
- UI の全文言を点検し、ROS の用語は必ず平易な言葉に言い換え、ROS の用語は括弧書きで併記する (例: 「チャンネル (トピック)」「届け方の設定 (QoS)」「設定値 (パラメータ)」「起動セット (launch ファイル)」)。
- 用語集を 1 か所 (i18n 辞書) にまとめ、言い換えの揺れをなくす。英語版でも同じ構造にする。

## 5. pub/sub の 1 枚絵 (案 C)
- 最初のチュートリアルの冒頭に、「処理の箱 (ノード) が、名前付きのチャンネル (トピック) に送る・購読する」を 1 枚の図で示す。送る側と受ける側は互いを知らない、名前だけで出会う、1 つのチャンネルに何人でも送れる・受けられる、の 3 点だけを伝える。
- 地図の凡例からいつでも開ける。

## 6. 検証
- E2E: ひな形から関数を作る → 地図で /chatter から入力口へ線を引く → 出力口から空白へ線を引く → 新しいトピックに大文字の値が流れる、をキーボード操作でも通す。
- 型が合わない配線が拒否されること、変換できる配線が許可されることの単体テスト。
