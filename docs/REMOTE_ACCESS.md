# roshanavi — 別マシンからのアクセス (設計)

シナリオ (P6) の後に実装予定。DESIGN.md へ統合する。

## 1. 方針
- **既定は localhost のみ** (現状維持)。別マシンからのアクセスは、起動オプション `--remote` で明示的に有効にする。
- roshanavi は「プロセスの起動・停止、ビルド、パラメータ変更、データ注入」ができる。これは開発 PC を遠隔操作できるのと同じなので、**認証なしでは絶対に公開しない**。
- 当面の安全な代替手段: SSH のポート転送 (`ssh -L 6871:localhost:6871 開発PC`)。新たな攻撃面を増やさずに、別マシンから見られる。README で案内する。

## 2. 鍵の登録 (デバイスのペアリング)
1. `--remote` で起動すると、サーバーのターミナルに **ペアリング用の URL とワンタイムコード** が出る (有効期限 10 分、1 回限り)。開発 PC の画面上で既にログイン済みのブラウザ (localhost) からも、「デバイスを追加」で発行できる。
2. 別マシンのブラウザでその URL を開き、コードを入力すると、そのブラウザに **デバイス鍵** (256 bit の乱数) が発行され、Cookie に保存される。
3. サーバーは鍵を **ハッシュ化して** `~/.config/roshanavi/devices.json` に保存する (平文は保存しない)。
4. 登録済みデバイスの一覧 (名前、権限、最終アクセス、IP) を UI で確認でき、いつでも失効できる。

### 権限
| 権限 | できること |
|---|---|
| 閲覧 (viewer) | 地図、トラフィック、エコー、ビューア、ログの閲覧 |
| 操作 (operator) | 上記に加えて、注入、ノードの起動・停止、パラメータ変更、ビルド、録画、シナリオ実行 |

ペアリング時に権限を選ぶ (既定は閲覧)。デバイスの追加・失効は、localhost からのみ行える。

## 3. 通信の保護
- **`--remote` では HTTPS を必須にする**。理由は 2 つある。
  - 平文の HTTP では、同じネットワークの他人にデバイス鍵を盗み見られる。
  - ブラウザのマイク・カメラ取得 (MEDIA §3) は、localhost 以外では HTTPS でないと使えない。
- 証明書は、利用者が用意したもの (`--tls-cert`, `--tls-key`) を使うか、無ければ自己署名証明書を自動生成する。自己署名の場合は、初回アクセス時の警告と照合できるように、証明書の指紋をターミナルに表示する。
- Cookie は `HttpOnly`、`Secure`、`SameSite=Strict`。
- CSRF 対策: 既存の Origin 検査に加えて、変更系のリクエストには独自ヘッダ (`X-Roshanavi-CSRF`) を必須にする。
- Host 許可リスト (既存の middleware) に、サーバーの LAN 上のホスト名・IP を `--remote` 時に自動で追加する。

## 4. 乱用への備え
- ペアリングコードの入力は回数制限し、失敗が続いたら一時的にロックする。
- **操作ログ**: どのデバイスが、いつ、何をしたか (ノード停止、注入、パラメータ変更など) を記録し、UI で確認できるようにする。企業での利用を想定した監査用。
- localhost からのアクセスは従来どおり鍵なしで使える (開発 PC の前にいる本人とみなす)。オプション `--require-auth-local` で localhost にも鍵を要求できる。

## 5. 制約
- ブラウザのマイク・カメラを別マシンから使う場合、音声と映像はネットワーク越しに送られる。その分の遅延が増えることを UI に明記する。
- インターネットへの直接公開は想定しない (LAN 内または VPN 内での利用を前提とする)。README に明記する。
