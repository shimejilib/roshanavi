# roshanavi 利用ガイド

roshanavi を使ってノードを開発する人のための、使い方の説明です。ROS 2 や Python のパッケージの仕組みに詳しくなくても読めるように書いています。各章の終わりには、うまくいかないときの表と、仕組みを知りたい人向けの [docs/design/](../design/) への案内があります。

まずは 1 章を見て、あとは必要な章を選んでください。

| 章 | 内容 |
|---|---|
| [はじめての起動と画面の見方](getting-started.md) | Docker での起動、各タブの役割、地図の読み方 (役割の色・線の状態・診断のバッジ・「受信なし」)、チュートリアル |
| [入力を流す](inputs.md) | 入力ノード (文字・数値・画像・音声など) とお試し送信、動画・画像・音声ファイル、ブラウザのマイク・カメラ、録画と再生 |
| [自分のコードを関数・クラスノードにする](user-code.md) | 自分の Python のコードをどこに置けば使えるか (A / B / C)、「ひな形を作る」、依存ライブラリの入れ方 (① rosdep ② 仮想環境)、よくあるつまずき、git のサブモジュール |
| [線でつないで作る](wiring.md) | 地図の上で、つなぎ口からトピックへ線を引いて関数・クラスノードをつなぐ、つなげない組み合わせと理由、外す・つなぎ替える、キーボードでの操作 |
| [ランチャーで自分のノードを動かす](launcher.md) | ノードの追加・起動・停止・再起動、ログ (絞り込みと検索)、パラメータのダイアログ (`__init__` の順・ROS の内部のパラメータの折りたたみ)、ビルドボタン、ノード一覧での一括操作・削除と元に戻す、lifecycle ノード |
| [既存の launch ファイルごと roshanavi で動かす](takeover.md) | `--launch` で今の launch ファイルのノードを roshanavi に起動させる、2 つの動かし方 (ノードごと / 全体)、launch ファイルを書き換えたとき、強制終了で残ったノードの片付け、いらないノードの削除 |
| [Docker で動いている既存のプロジェクトに入れる](docker-integration.md) | プロジェクトのイメージに roshanavi を重ねて、compose にコンテナを 1 つ足す手順 (Dockerfile・compose の例)、元の起動方法を残す方法、既知の注意点 |
| [動いているシステムを見るだけ](observe.md) | 手を入れずに横から見る (ROS_DOMAIN_ID を合わせる)。できること・できないこと、Docker のネットワークと共有メモリ、独自のメッセージ型 |
| [シナリオで確かめる・テストに組み込む](scenarios.md) | 画面の操作を記録してシナリオを作る、編集・実行、失敗の説明、コマンドラインと CI (JUnit)、launch_pytest、CPU・メモリのチェック |
| [測る (トラフィック・詳細計測・リソース)](measure.md) | トラフィックの表と「値の根拠」、重いデータの扱い、詳細計測モード、リソースとメモリリークの検出 (精度と限界)、規模と負荷の限界 |
| [困ったときの一覧](troubleshooting.md) | 症状から原因と直し方を引く表 (地図に何も出ない・QoS の不一致・トピック名の打ち間違い・未対応の型・CPU が高い・UDP バッファ・強制終了の残り物・Docker・マイク/カメラの許可など) |
| [用語集](glossary.md) | ノード、トピック、QoS、メッセージ型、パラメータ、launch ファイル、lifecycle、composable container、ROS_DOMAIN_ID、RMW、tf など。画面のどこに出てくるかも書いてある |
| [自分のワークスペースに入れる](install.md) | ソースからビルドして `ros2 run roshanavi app` で動かす、いまの Web 画面の作り方、対応している ROS 2 |
| [別のマシンから roshanavi を見る (SSH)](remote-ssh.md) | SSH のポート転送で手元のブラウザから見る、Docker の場合、Windows + WSL2 の場合、ロボットの PC の場合、うまくいかないとき |

用語は、ROS の公式の用語をそのまま使っています (トピック、パラメータ、launch ファイル、QoS など)。ROS の資料や `ros2 topic` のコマンド、エラーメッセージとそのまま対応します。意味は画面の ⓘ (用語の上にマウスを置く)、[はじめに](getting-started.md#用語集) の用語集、[design/wiring.md](../design/wiring.md) で確かめられます。
