# 困ったときの一覧

「こうなった」から原因と直し方を引ける一覧です。各章の「うまくいかないとき」を、症状ごとに 1 か所へ集めました。表の右の列から、くわしい章へ移れます。

まず次の 3 つを見ると、半分くらいはここで片付きます。

1. 画面の右上が「接続済み」になっているか。「切断 (再接続中)」なら、roshanavi のサーバーが止まっています (Docker なら `docker compose logs lab`)。
2. 地図の上の「診断」に件数が出ていないか。QoS の不一致や、トピック名の打ち間違いは、ここに理由つきで出ます。
3. 見たいノードと roshanavi の `ROS_DOMAIN_ID` (ノード同士の仲間分けの番号) が同じか。

## 1. 地図・つながり

| 症状 | 原因 | 直し方 | くわしくは |
|---|---|---|---|
| 地図に何も出ない | `ROS_DOMAIN_ID` が違う。見たいノードと roshanavi は、同じ番号でないと見えません | 見たいノードの端末で `echo $ROS_DOMAIN_ID` を確かめ、roshanavi を同じ番号で起動する。同じ環境で `ros2 topic list` が見えるかも確かめる | [動いているシステムを見るだけ](observe.md) |
| 同じマシンのノードは見えるが、別のマシンのノードが見えない | 探し合いが「このマシンの中だけ」になっている。`ROS_LOCALHOST_ONLY=1` や `ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST` が設定されている | 両方のマシンで、その環境変数を外して既定に戻す。ファイアウォールが UDP を止めていないかも確かめる | [動いているシステムを見るだけ](observe.md) |
| Docker のコンテナの間でだけ見えない | ネットワークが別 (別の compose プロジェクトは別のネットワーク)。または `/dev/shm` が共有されていない | 同じネットワークに入れるか `network_mode: host` にする。`ipc: host` などで共有メモリを共有する (6 章) | [動いているシステムを見るだけ](observe.md) |
| ノードは出るが、データが来ない・Hz が出ない | RMW (ROS の通信の実装) が違う。共有メモリが共有されていない | 両方で `RMW_IMPLEMENTATION` を同じにする。Docker は 6 章 | [動いているシステムを見るだけ](observe.md) |
| 線が赤い破線で、データが届かない | QoS (届け方の約束) の不一致。送る側と受け取る側の約束が合っていない | 診断の説明を読む。典型は、送る側が `BEST_EFFORT` で受け取る側が `RELIABLE` のとき。受け取る側を `BEST_EFFORT` にするか、送る側を `RELIABLE` にそろえる。チュートリアルの「QoS の直し方」でも練習できます | [はじめての起動と画面の見方](getting-started.md) |
| 「名前が似ているトピック」と診断される | トピック名の打ち間違い (`/cmd_vel` と `/cmdvel` など)。片方にしか送る側 (または受ける側) がいない | どちらかの名前を直す。意図した別のトピックなら、無視して構いません | [はじめての起動と画面の見方](getting-started.md)、[入力を流す](inputs.md) |
| 「受信なし」「送信なし」の印が出る | 診断ではなく、いまは送るだけ (または受け取り待ちだけ) という状態です。組み立て中は普通です | 作っている途中なら、そのままで構いません。相手がいるはずなら、トピック名と `ROS_DOMAIN_ID` を確かめる | [はじめての起動と画面の見方](getting-started.md) |
| 「さっきまでいたのにいなくなった」と出る | 直近 5 分に動いていたノードが消えた。落ちたか、止めたか | ランチャーでそのノードのログを見る ([ランチャー](launcher.md))。意図して止めたなら、数分で消えます | [はじめての起動と画面の見方](getting-started.md) |
| 「未対応の型」と出て、中身が見えない | その型 (メッセージ型) の定義が、roshanavi の動いている環境に入っていない。独自のメッセージ型でよく起きます | 型を定義したパッケージを、roshanavi と同じ環境に入れる (ワークスペースを source した端末で起動する。Docker はそのパッケージが入ったイメージの上に重ねる) | [動いているシステムを見るだけ](observe.md)、[Docker で動いている既存のプロジェクトに入れる](docker-integration.md) |
| 起動したノードが地図に出ない | ノードが ROS のノードとして起動していない (すぐ終了した)、または `ROS_DOMAIN_ID` が違う | ランチャーのログで終了コードとエラーを見る。同じ番号か確かめる | [ランチャーで自分のノードを動かす](launcher.md) |
| 「停止」が灰色で押せない | 仕様です。roshanavi が起動していないノードには、シグナルを送りません | 止めたいなら、roshanavi から起動し直す。今の launch ファイルごと引き取ることもできます | [既存の launch ファイルごと roshanavi で動かす](takeover.md) |

## 2. 計測

| 症状 | 原因 | 直し方 | くわしくは |
|---|---|---|---|
| 画像・点群のトピックの Hz が「非監視」で出ない | 重いデータ (画像・点群など) は、計測の負荷が大きいので、既定では計測しません | トピックを選んで監視を ON にする。または詳細計測モードを使う | [測る](measure.md) |
| Hz が「計測中…」や「—」のまま | 数秒に 1 回以下のゆっくりしたトピックは、少し待っても値が決まりません。止まっているなら 0 / 「停止中」です | 流れるのを待つ。計算期間を 10 秒に伸ばす | [測る](measure.md) |
| 受け取る側の Hz が「理論値」のまま | 詳細計測モードがオフ、または測れないノードです。理論値は「届くはずの量」です | 詳細計測モードを ON にする。測れない理由は画面の下に出る | [測る](measure.md) |
| 詳細計測モード (トレース) のスイッチが押せない・「使えません」と出る | `lttng-tools` と `python3-bt2` が入っていない。Docker では共有メモリが足りない。または `--tracing off` で起動している | `sudo apt install lttng-tools python3-bt2`。Docker は `shm_size: 512m` を付ける | [測る](measure.md) |
| 詳細計測で「測れないノード」と出る | roshanavi と別のコンテナや別のマシンにいる。roshanavi より前から動いている。Python のノードは受け取った数しか測れない | 同じ場所で動かす。前から動いているノードは再起動する | [測る](measure.md) |
| 取りこぼしが出る | 数の欠け (送った番号の欠番)。受け取る側の処理が遅くて捨てている、またはネットワークや UDP バッファの問題 | 詳細計測モードで「処理が追いついていません」が出ないか見る。大きなデータなら次の 3 章を見る | [測る](measure.md) |
| ノードの CPU・メモリが出ない | 別のマシンや別のコンテナのノード。roshanavi が見られるのは、同じ場所のプロセスだけ | roshanavi を同じマシン (同じコンテナ) で動かす | [測る](measure.md) |

## 3. CPU が高い・取りこぼす

| 症状 | 原因 | 直し方 | くわしくは |
|---|---|---|---|
| Python のノードが、ほとんど仕事をしていないのに CPU を 1 コア近く使う | `MultiThreadedExecutor` (複数のスレッドでコールバックを処理する仕組み) と Fast DDS、rclpy の既定の QoS イベント通知の組み合わせで、待ちのループが空回りしている | 購読に `event_callbacks=SubscriptionEventCallbacks(use_default_callbacks=False)` を渡す。並列が要らなければ `SingleThreadedExecutor` にする。体験用のサンプル `busy_demo` (⚙ のプロジェクト切り替え) で、3 つの構成を 1 つずつ起動して比べられます | [測る](measure.md)、[design/measurement.md](../design/measurement.md#cpu-が高い-multithreadedexecutor-の空回り) |
| 大きなデータ (画像・点群) を取りこぼす。リソースタブで UDP 受信バッファ溢れの件数が増える | OS の UDP 受信バッファが小さくて、大きなメッセージが溢れている | OS の `net.core.rmem_max` を大きくする (下の「UDP 受信バッファを大きくする」) | [測る](measure.md) |

### UDP 受信バッファを大きくする

診断に「受信バッファ不足の可能性があります。`net.core.rmem_max` の引き上げを検討してください」と出たときの手順です。ROS 2 は大きなデータを UDP で送るので、OS の受信バッファが小さいと溢れます。

```bash
sysctl net.core.rmem_max
```

```bash
sudo sysctl -w net.core.rmem_max=134217728
```

これは再起動すると元に戻ります。残したいときは `/etc/sysctl.d/` に `net.core.rmem_max=134217728` と書いたファイルを置きます。Docker のコンテナはホストのカーネルの設定を使うので、ホストで設定します。送るノード側の DDS の設定 (Fast DDS のプロファイルなど) も関係することがあります。

## 4. パラメータ・ランチャー

| 症状 | 原因 | 直し方 | くわしくは |
|---|---|---|---|
| パラメータの一覧や変更が「時間切れ」になる | ノードが応答していない (起動の直後、マシンが忙しい、ノードがパラメータのサービスを持っていない) | 少し待って「読み直す」。変更のときは、反映済みかもしれないので、読み直して確かめる。ノードが重いときは、roshanavi の起動時に `--service-timeout 秒数` で待ち時間を延ばせる | [ランチャーで自分のノードを動かす](launcher.md) |
| パラメータの「変更」が押せない | 読み取り専用、型が未設定、または roshanavi の外のノード (「変更を許可する」が先) | 該当の理由が行に出る | [ランチャーで自分のノードを動かす](launcher.md) |
| ビルドに失敗する | `colcon` が無い、依存が入っていない、コードのエラー | 「ビルドログを見る」で最初のエラーを読む。依存は `rosdep install` | [ランチャーで自分のノードを動かす](launcher.md)、[自分のワークスペースに入れる](install.md) |
| 関数・クラスノードの候補が一覧に出ない | `__init__.py` や `package.xml` が無い、関数がトップレベルにない、など | 「コードの場所」の「候補にならなかったもの」に理由が出る | [自分のコードを関数・クラスノードにする](user-code.md) |

## 5. 強制終了のあとの残り物

roshanavi を `kill -9` やメモリ不足で強制終了すると、起動したノードが残ることがあります。

| 症状 | 直し方 |
|---|---|
| 起動直後、画面の上に「前回の roshanavi が起動したノードが残っています (N 個)。止めますか?」と出る | 「止める」を押す。roshanavi が起動を記録したプロセスのうち、起動時刻とコマンドラインが一致するものだけを止めます。ほかのプログラムには触れません |
| 画面なしで片付けたい | `ros2 run roshanavi cleanup`。`--dry-run` を付けると、止めずに一覧だけ出します。`--data-dir` は、roshanavi を起動したときと同じものを指定する |
| Docker の中で強制終了した | `docker restart <コンテナ名>` が確実 (コンテナの中のすべてが止まります。compose の `init: true` が前提) |

くわしくは [既存の launch ファイルごと roshanavi で動かす](takeover.md) の「強制終了されたとき」にあります。

## 6. Docker

| 症状 | 原因 | 直し方 | くわしくは |
|---|---|---|---|
| `docker compose build` が `npm ci` や `apt-get` で失敗する (社内ネットワークなど) | `docker build` は端末のプロキシの環境変数を使わない | `~/.docker/config.json` の `proxies` にプロキシを書く。ベースイメージの取得はデーモン側の設定 (Docker Desktop は Settings → Resources → Proxies) | [README の「試す (Docker)」](https://github.com/shimejilib/roshanavi#試す-docker) |
| ビルドや起動が、思っていない ROS の版 (Humble など) になる | ホストで ROS を `source` した端末では `ROS_DISTRO` がその版になっていて、compose がそれを使う | `ROS_DISTRO=jazzy` (または `lyrical`) を付けて実行する | [README の「試す (Docker)」](https://github.com/shimejilib/roshanavi#試す-docker) |
| ブラウザで開けない | コンテナが動いていない。ポート 6871 を別のものが使っている | `docker compose ps` で `lab` を確かめる。別のポートに変えるときは `--port` | [はじめての起動と画面の見方](getting-started.md) |
| 別のマシンのブラウザから開けない | 安全のため、roshanavi は `localhost` からだけ開けます | SSH のポート転送を使う | [別のマシンから見る (SSH)](remote-ssh.md) |
| 詳細計測モードで何も記録されない | 共有メモリ (`/dev/shm`) が小さい | compose に `shm_size: 512m` を付ける | [測る](measure.md)、[Docker で動いている既存のプロジェクトに入れる](docker-integration.md) |
| コンテナの間で、ノードが見えない・データが来ない | ネットワークが別、または `/dev/shm` が共有されていない (Fast DDS は同じマシンでは共有メモリでデータを渡す) | 同じネットワーク (または `network_mode: host`) と、共有メモリ (`ipc: host` など) をそろえる | [動いているシステムを見るだけ](observe.md) |
| 画面が真っ白、または API の文字だけ出る | 画面のビルド済みファイルがイメージに入っていない | イメージのビルドで画面の段が成功したか、`ROSHANAVI_STATIC_DIR` が正しいかを確かめる | [Docker で動いている既存のプロジェクトに入れる](docker-integration.md) |
| 画面を直したのに古いまま | イメージに古い画面が入っている | `docker compose build lab` をして起動し直す | [はじめての起動と画面の見方](getting-started.md) |

## 7. ブラウザのマイク・カメラ

| 症状 | 原因 | 直し方 | くわしくは |
|---|---|---|---|
| マイク・カメラが選べない・許可のダイアログが出ない | ブラウザは、安全な場所 (`http://localhost` か `https://`) でしかマイク・カメラを許可しません。別のマシンの IP アドレスで開いていると使えません | `http://localhost:6871` で開く。別のマシンから使うときは SSH のポート転送で `localhost` にする | [入力を流す](inputs.md)、[別のマシンから見る (SSH)](remote-ssh.md) |
| 一度「ブロック」を押してしまった | ブラウザがその設定を覚えています | アドレスバーの鍵アイコンなどから、マイク・カメラの許可を「許可」に戻して、ページを読み込み直す | [入力を流す](inputs.md) |
| 音や映像が流れない | 同じトピックに、すでにブラウザ入力が使われている (1 トピックに 1 つまで) | 先に動いているものを止めてから始める | [入力を流す](inputs.md) |

## 8. シナリオ・入力

| 症状 | 原因 | 直し方 | くわしくは |
|---|---|---|---|
| 送ったのにノードが反応しない | QoS の不一致、またはトピック名の打ち間違い | 地図の診断を見る。送り先のトピック名が、ノードが受け取るトピックと完全に同じか確かめる | [入力を流す](inputs.md) |
| 「この型は作れない」と出る | その型は、入力ノードやメディアの送信にまだ対応していない | 録画した bag を再生する | [入力を流す](inputs.md) |
| シナリオが「届くはず」で失敗する | 待ち時間 (`within`) が短い、トピック名の打ち間違い、QoS の不一致 | 失敗の説明の「原因の候補」を読む | [シナリオで確かめる](scenarios.md) |
| 録画が自動で止まった | data フォルダの空き容量が足りない | 空きを作る。しきい値は起動オプションで変えられる | [入力を流す](inputs.md) |

## それでも分からないとき

- [用語集](glossary.md) で、画面に出てくる言葉の意味を確かめる。
- 再現する手順、ROS のディストロ (Jazzy / Lyrical など)、RMW、Docker かネイティブか、画面のスクリーンショットを添えて、GitHub の Issues に書いてください。
- 設計の背景を知りたいときは、各章の最後にある「仕組みを知りたい人へ」のリンクから進めます。
