# 動いているシステムを見るだけ

すでに動いているシステム (ロボット、他の人が動かしているノード、手を入れたくない環境) に、**何も変えずに**横から roshanavi をつないで、様子を見る方法です。ノードの起動セット (launch ファイル) も、Docker の設定も書き換えません。

手を入れてよいなら、[既存の起動セットごと動かす](takeover.md) か [Docker で動いている既存のプロジェクトに入れる](docker-integration.md) のほうが、できることがずっと多くなります (下の表)。

## 1. 仕組み

ROS 2 のノードは、同じ ROS_DOMAIN_ID (仲間分けの番号) の中なら、お互いを自動で見つけます。roshanavi も 1 つのノードとしてその中に入り、見える範囲の情報から地図とトラフィックを作ります。だから **見たいノードと同じ ROS_DOMAIN_ID にして起動する**だけで、地図に現れます。

```bash
export ROS_DOMAIN_ID=31        # 見たいシステムと同じ番号
ros2 run roshanavi app         # ワークスペースを source した端末で
```

ブラウザで http://localhost:6871 を開きます。

## 2. 手を入れずに「できること / できないこと」

| | 観察だけ (この章) | 起動セットごと動かす / Docker に入れる |
|---|---|---|
| 地図、診断 (つながっていない所の指摘) | できる | できる |
| トラフィック (Hz・帯域・取りこぼし) | できる (送信元のノードごとの実測) | できる |
| チャンネルの中身を見る (エコー) | できる (型を roshanavi の側でも読めれば) | できる |
| 入力ノード・お試し送信・録画・再生 | できる | できる |
| 変換ノード・関数ノード | できる | できる |
| シナリオ (送って → 出力を判定) | できる | できる |
| **ノードの停止・再起動・ログ** | **できない** (roshanavi が起動したものだけ操作します。他のプロセスには何もしません) | できる |
| ビルドして再起動 | できない | できる |
| ノードごとの CPU・メモリ、メモリリークの診断 | roshanavi と**同じ PC のプロセスだけ**。別の PC・別のコンテナのノードは見えない | 正確 |
| 詳細計測モード (トレース) | **できない** (roshanavi より前から動いているノードや、別のコンテナのノードは測れません。画面に「測れないノード」と理由が出ます) | できる |

## 3. Docker で動いているシステムを見る

ROS のノードが Docker のコンテナで動いているとき、roshanavi を別のコンテナとして足す形です。この組み方の詳しい手順と検証は [#42](https://github.com/shimejilib/roshanavi/issues/42) で整備中なので、ここには、確かめられている考え方だけを書きます。

見えるようにする条件は 3 つです。

1. **同じ ROS_DOMAIN_ID と、同じ RMW** (`RMW_IMPLEMENTATION`)。
2. **ネットワークがつながっている**。別々の compose プロジェクトは、別のネットワークになるので、そのままでは互いに見えません。確実なのは、見たいコンテナと同じネットワークに入れるか、`network_mode: host` にすることです。
3. **共有メモリ (/dev/shm)**。同じパソコンの Fast DDS は共有メモリでデータを渡します。コンテナの間で共有されていないと、ノードの発見はできても、データが届かない・取りこぼしが増えることがあります。`ipc: host` などで共有するか、確かめてください。

```yaml
# 例 (観察だけのコンテナ)。見たい側のコンテナと条件をそろえる
services:
  roshanavi:
    image: <roshanavi のイメージ>
    network_mode: host
    ipc: host
    environment:
      ROS_DOMAIN_ID: "31"
    command: ["ros2", "run", "roshanavi", "app"]
```

`network_mode: host` だと、ポート 6871 はコンテナからそのままパソコンに開きます (`ports:` は不要です)。ネットワークに自分以外が入れる場合は、roshanavi を `127.0.0.1` だけで待ち受けさせるのが既定です。理由なく `--host 0.0.0.0` にしないでください。

## 4. 独自のメッセージ型 (自分で定義したデータの形)

自分で定義したメッセージ型 (`my_msgs/msg/Detection` など) を使うトピックの中身を、roshanavi が読むには、**roshanavi の側にも、その型のパッケージが入っている**必要があります。

- 入っていない: 型が読めないため、「未対応の型」と出ます。中身の表示 (エコー)、入力・シナリオでの判定は使えません。
- 入っている: 他の型と同じように、中身の表示、入力、判定ができます。

Docker では、ノードの側のイメージを土台にして roshanavi を重ねる (`FROM <自分のイメージ>`) と、型がそのまま入ります ([Docker で動いている既存のプロジェクトに入れる](docker-integration.md))。ネイティブでは、自分のワークスペースを source してから起動します。

## うまくいかないとき

| 症状 | 確かめること |
|---|---|
| 地図に何も出ない | ROS_DOMAIN_ID が同じか。`ros2 topic list` を同じ環境で実行して、見えるか。`ROS_LOCALHOST_ONLY=1` や `ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST` が設定されていると、他のマシンのノードは見えません |
| ノードは出るが、Hz が出ない・データが来ない | 共有メモリ (`/dev/shm`) が共有されているか。Docker のネットワークが別でないか。RMW が同じか |
| コンテナの間でだけ見えない | 同じネットワークか、`network_mode: host` か。別の compose プロジェクトは別のネットワークです |
| 「停止」が灰色で押せない | 仕様です。roshanavi が起動していないノードは止めません。止めたいなら [起動セットごと動かす](takeover.md) |
| 詳細計測モードで「測れないノード」と出る | 観察だけの構成では測れません。理由は画面に出ます |
| 中身を表示できない | 独自の型が roshanavi の側に入っているか (上の 4.) |
| 別のマシンのブラウザから開きたい | [SSH のポート転送](remote-ssh.md) |
