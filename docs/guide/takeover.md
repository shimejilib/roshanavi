# 既存の launch ファイルごと roshanavi で動かす

いつも `ros2 launch <パッケージ> <launch ファイル>` で動かしているシステムを、そのまま roshanavi に起動させる方法です。launch ファイルは書き換えません。roshanavi が中のノードを 1 つずつ起動するので、次のことができるようになります。

- ノードを 1 つだけ止める・再起動する・ログを見る (ほかのノードは動いたまま)
- 開発中のノードだけビルドし直して再起動する
- ノードごとの CPU・メモリ、詳細計測 (トレース)

設計の詳しい説明は [design/integration.md](../design/integration.md) にあります。

## 1. 起動する

```
ros2 run roshanavi server --launch turtle_patrol patrol.launch.py side_length:=2.0 --mine patrol
```

- `--launch` のあとに、`ros2 launch` と同じ順で **パッケージ名・launch ファイル名・引数 (`名前:=値`)** を書きます。
- `--mine <ノード名>` は「自分が開発しているノード」です (地図で色が変わります)。何度でも書けます。あとから画面で変えることもできます。
- ブラウザで http://localhost:6871 を開くと、ノード一覧に launch ファイルのノードが並び、すべて動いています。

bringup の launch ファイルから使うときは、次のように書けます。

```
ros2 launch roshanavi takeover.launch.py package:=turtle_patrol launch_file:=patrol.launch.py \
    args:='side_length:=2.0' mine:=patrol
```

## 2. 2 つの動かし方 (`--launch-mode`)

| | `node` (既定) | `whole` |
|---|---|---|
| どう動くか | ノードを 1 つずつ別々に起動する | launch ファイル全体を 1 つとして起動する (`ros2 launch` と同じ) |
| 止める・再起動 | ノードごと | 全体をまとめて |
| launch ファイルの動作 | 一部が元どおりにならない (下) | 元どおり |

`node` では、launch ファイルのうち 1 つずつに分けられない部分 (ノードでないプログラム、コンポーザブルノードのコンテナ、時間をおいて起動する `TimerAction` など) を「残りの部分」として 1 つにまとめて、元どおりに動かします。

ノードを 1 つずつ動かすと、次の動作は元どおりになりません。当てはまるものがあると、画面の上に「ノードを 1 つずつ動かすと、launch ファイルの動作のうち N 件が元どおりになりません」と出ます。「詳しく」で、どのノードの何が変わるかを確かめられます。

- **required ノード** (`on_exit=Shutdown()`): そのノードが終わっても、ほかのノードは止まりません。
- **イベント** (`OnProcessExit` / `OnProcessStart` など、あるノードの起動・終了をきっかけに動く処理): 働かないことがあります。
- **時間をおいた起動** (`TimerAction`): 遅れて起動はしますが、ほかのノードとの順番は保証されません。
- **条件** (`if` / `unless`): roshanavi が取り込んだときの引数で決まります。

引き継げるものは引き継ぎます。

- **`respawn=True`** (落ちたら起動し直す) → roshanavi の「自動再起動」(待ち時間は 1, 2, 4 … 最大 30 秒)。
- **launch ファイルの中で設定した環境変数** → 各ノードの起動設定へ。ただし `LD_PRELOAD` や `PYTHONPATH` のように、どのプログラムを読み込むかを左右するものは安全のため引き継ぎません (画面に名前が出ます)。

元どおりの動作が必要なときは、`--launch-mode whole` を付けて起動し直してください。

## 3. launch ファイルを書き換えたとき

launch ファイルが正です。roshanavi は別の設定を持たないので、launch ファイルを書き換えると、画面の上に **「launch ファイルが変更されました。取り込み直しますか?」** と出ます。

1. 「変更を見る」で、追加されるノード・なくなるノード・設定が変わるノードを確かめます。
2. 「取り込み直す」を押すと、**変わったノードだけ** を止めて起動し直します。変わっていないノードは動き続けます。
3. 今は取り込まないときは「あとで」。次に launch ファイルが変わったときに、また聞きます。

- roshanavi のビルドボタン (`--symlink-install`) でビルドしたパッケージなら、`src/` の launch ファイルを保存しただけで気づきます。そうでないときは、ビルドし直したときに気づきます。
- 中身が同じまま保存し直しただけ (ビルドで同じファイルがコピーされた等) なら、何も聞きません。
- roshanavi を止めている間に launch ファイルが変わったときは、次に起動したとき、前回の内容で動かしてから「取り込み直しますか?」と聞きます。

## 4. roshanavi を起動し直したとき

同じ launch ファイルと引数で起動し直すと、前回のノード (と、画面で変えた役割など) をそのまま使います。同じノードが 2 つできることはありません。引数を変えて起動し直すと、同じノードの設定がその引数に合わせて変わります。

## 5. Docker で使う

利用者のイメージの上に roshanavi を重ねたコンテナを 1 つ作り、その中で `--launch` を付けて起動します。元の起動方法 (roshanavi なし) は compose の profile に残しておくと、いつでも切り替えられます。例は `[turtle_demo](../turtle_demo.md)` の `docker-compose.yml` (`dev` サービスと profile `plain`) です。

## 6. roshanavi が強制終了されたとき

roshanavi を `kill -9` などで強制終了すると、roshanavi が起動したノードが残ることがあります (`ros2 run` の先のノードは、親が急にいなくなっても気づかないため)。

- **Docker**: `docker restart <コンテナ名>` がいちばん確実です (コンテナの中のすべてが止まります)。
- **Docker でないとき**: `ros2 run roshanavi cleanup` を実行します (`--data-dir` は roshanavi を起動したときと同じもの)。`--dry-run` を付けると、止めずに一覧だけ出します。
- 次に roshanavi を起動すると、画面の上に **「前回の roshanavi が起動したノードが残っています (N 個)。止めますか?」** と出ます。「止める」で同じ片付けをします。

どれも、roshanavi が起動を記録したプロセスのうち、起動時刻とコマンドラインが記録と一致するものだけを止めます。ほかのプログラムには触れません。

## 7. いらなくなったノードを消す

ノード一覧でチェックして「削除」を押すと、roshanavi の登録 (起動リストなど) から外し、動いていれば止めます。**ソースコード・パッケージ・パラメータファイルは消えません。** 削除してから 10 秒間は「元に戻す」で戻せます。launch ファイルから引き取ったノードは、launch ファイルを取り込み直すとまた現れます (いらないノードは launch ファイルから消してください)。
