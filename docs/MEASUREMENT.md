## 3. トレース計測 (詳細計測モード)

### 3.1 構成 (どの層のツールか)
```
[対象ノード]  アプリのコード
               rclcpp / rclpy   ← トレースポイント (callback_start/end, take など)
               rcl              ← トレースポイント
               rmw              ← トレースポイント (publish / take)
               DDS
                 │ tracetools (ros2_tracing) が LTTng-UST の API でイベントを記録
                 ▼
[LTTng-UST]   対象プロセス内のライブラリ。共有メモリ上の CPU ごとのリングバッファに書く
                 ▼
[lttng-tools] セッションデーモン / コンシューマデーモン (別プロセス)。バッファを回収しファイル (CTF 形式) に保存
                 ▼
[roshanavi]   一定間隔でトレースを読み (babeltrace2)、ノード × トピックの受信数・処理数・処理時間を集計
```
- LTTng は Linux のトレーシング基盤。ユーザー空間用 (**LTTng-UST**) とカーネル用 (LTTng-modules) があり、roshanavi が使うのは **ユーザー空間用のみ** (root 権限・カーネルモジュール不要)。
- ros2_tracing (tracetools) は ROS 2 側のトレースポイント定義。Jazzy の公式バイナリにはトレースポイントが組み込まれており、LTTng をインストールすれば有効になる (実装時に `ros2 run tracetools status` で確認する)。
- Python ノード (rclpy) で取れるイベントの種類は、C++ ノードより少ない可能性がある。実装時に確認し、取れない項目は UI で「未対応」と表示する。

### 3.2 取れるもの
- ノード × トピックごとの **受信数** (take) と **処理数** (コールバック実行)。差があれば「受け取っているが処理が追いついていない」と診断する。
- コールバックごとの **処理時間** (平均・p95・最大)。

### 3.3 負荷の見積もり (UI と README に明記する)

**対象ノード側 (計測される側)**
- 有効化されたトレースポイント 1 回あたりのコストは、数百 ns 程度 (CPU ごとのリングバッファへの書き込みのみで、ロックやシステムコールを伴わない)。無効時はほぼゼロ。
- 1 メッセージあたり、送信側で約 3 イベント、受信側で約 5 イベントが記録される。合計で **1 メッセージあたり数 µs 程度** の CPU 時間。
- 例: 1 kHz のトピックでも、CPU 1 コアの約 0.1〜0.5%。30 Hz の画像トピックなら無視できる水準。
- メッセージの遅延 (レイテンシ) への影響も、1 メッセージあたり数 µs 程度。

**roshanavi 側 (計測する側) — 実際の負荷の大半はこちら**
- メモリ: リングバッファ。既定で CPU 1 個あたり 4 MiB 程度 (8 CPU なら約 32 MiB)。
- ディスク: 1 イベントあたり約 50〜100 バイト。例として、100 Hz のトピック 10 本ではイベントが毎秒約 8,000 件になり、**約 0.6 MB/秒 (1 時間で約 2 GB)**。roshanavi は一定間隔でトレースを区切り (セッションのローテーション)、集計済みの区切りを削除するので、ディスク使用量は数十 MB 程度に抑える。
- CPU: トレースの解析 (Python の babeltrace2)。毎秒数千イベント規模で CPU 1 コアの数十%に達する可能性がある。同じ PC の他のノードに影響するため、roshanavi 自身の CPU 使用率を常に表示する (RESOURCES.md の観測者効果の確認)。
- 表示の遅れ: 区切りごとに解析するため、1〜2 秒遅れる。

**取りこぼし**
- バッファが溢れた場合、LTTng はイベントを捨てる (対象ノードを止めないため)。捨てた件数は記録されるので、UI で「計測の取りこぼし N 件」と表示する。

**検証**
- 上の数値は文献と仕組みからの見積もり。実装時にベンチマーク (トレースのオン・オフで、対象ノードの CPU 使用率とレイテンシを比較) を取り、実測値を README に載せる。

### 3.4 制約
- 計測できるのは roshanavi と同じ PC (Docker の場合は同じコンテナ、または lttng のセッションデーモンを共有する構成) のノードのみ。
- lttng-tools と LTTng-UST のインストールが必要 (未導入なら、UI で導入方法を案内する)。
- 既定はオフ。詳細計測モードを有効にしている間だけトレースする。
