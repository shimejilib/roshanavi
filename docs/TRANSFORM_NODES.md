# roshanavi — 変換ノード (topic A を受けて topic B に出すノード)

P5 (サンプルノード) と合わせて実装予定。DESIGN.md へ統合する。

## 1. 目的
入力ノード (ダミー) は「一方的に送る」だけだった。変換ノードは **トピックを受信し、変換して別のトピックに送る** ノードを、コードを書かずに GUI で作る。

主な用途:
- **未実装・未到着のノードの代役 (モック)**: パイプラインの途中のノードがまだ無いとき、それらしい出力を返す代役を置いて、自分のノードを先に試す。
- **つなぎ合わせ**: 名前や型が合わないトピック同士を変換してつなぐ。
- **意地悪テスト**: 遅延・間引き・取りこぼしを入れて、下流のノードの耐性を確かめる。

## 2. できること
| 機能 | 例 |
|---|---|
| フィールドの対応づけ (式) | `B.data = upper(msg.data)`、`B.linear.x = msg.linear.x * 0.5` |
| 条件で送る / 捨てる | `msg.data != ''` のときだけ送る |
| 型の変換 | `std_msgs/String` → `std_msgs/Int32` (`int(msg.data)`) |
| そのまま中継 | 型も中身もそのまま、名前だけ変える (relay) |
| 遅延 | 受信から一定時間 (または乱数の範囲) 遅らせて送る |
| 間引き | 最大 N Hz に制限する (throttle) |
| 取りこぼし | 一定の割合で捨てる |
| 複数入力 | 複数のトピックの最新値を組み合わせて 1 つの出力を作る (どれかが更新されたら送る / 指定トピックの受信時に送る) |

## 3. 式
- 既存の安全な式評価器 (§4.5、eval 不使用) を拡張し、入力メッセージを `msg` (複数入力のときは `msg1`, `msg2` …、またはトピック名の別名) として参照できるようにする。
- 許可するのは **入力メッセージのフィールド参照 (ドット区切り・配列添字) に限った** 属性アクセスと添字アクセス。それ以外の属性アクセスは引き続き拒否する。
- 関数を追加する: `upper lower len strip replace` (文字列)、`clamp` (数値)、`now_stamp()` (現在時刻の stamp)。
- 出力メッセージの各フィールドは、テンプレート (型から自動生成) に式を書き込んで指定する (入力ノードと同じ編集画面)。

## 4. 実体と管理
- 恒久ダミーノードと同じ仕組みで、独立したノードとして動く (`ros2 run roshanavi transform --config <yaml>`)。
- 地図上の役割は「ダミー」と同じ系統の色 (ラベルは「変換」) にする。
- プロジェクトファイルに保存し、自動起動・停止・再起動・launch への書き出しができる。
- 大きいメッセージ (画像・点群) は、MVP では「そのまま中継・遅延・間引き・取りこぼし」のみ対応する (フィールド単位の式の変換は対象外)。

## 5. UI
- 地図でトピックを右クリック →「このトピックを受けて変換するノードを作る」。
- 「＋ 入力ノードを作る」の隣に「＋ 変換ノードを作る」。
- 作成画面に、入力メッセージの最新値を左、変換結果のプレビューを右に並べ、式を書くとその場で結果が見えるようにする。

## 6. 参考
- ROS 1 の `topic_tools transform` (Python 式で変換) に相当する機能を、安全な式評価と GUI で提供する位置づけ。
